## U2-D1: Functions, Domain, Range, and End Behavior

Classroom flow:
- Function starts with the vending-machine metaphor: one input should produce one output.
- Relation is any input/output pairing; function is a stricter relation.
- Inputs are `x`; outputs are `y`.
- Domain is what can be plugged in for `x`; range is what can come out as `y`.
- Square-root domain is introduced by contrast: `sqrt(x)` allows `x >= 0`, but not negative inputs.
- Vertical Line Test is the graph test for whether one input has more than one output.
- Mapping diagrams and ordered pairs are used to catch repeated inputs with different outputs.
- Discrete sets use braces; continuous intervals use interval notation.
- Open circles use parentheses; closed circles use brackets.
- Infinity always uses parentheses.
- Domain is read left to right; range is read low to high.
- End behavior only exists when the graph continues forever in that direction.

Tool implications:
- Piecewise Function Grapher should include an interval-notation readout for domain/range, not just point evaluation.
- A Function or Not sorter would help: graph, mapping diagram, ordered-pair set, and verbal relation modes.
- Domain/range tools should explicitly distinguish discrete braces from interval notation.
- End-behavior chips should include a "does not exist" state when a graph stops.

## U2-D2: Calculator Workflow

Classroom flow:
- TI-style calculator use is taught as a workflow, not as a replacement for algebra.
- Students learn:
  - previous-answer reuse.
  - delete vs clear.
  - negative sign vs subtraction sign.
  - fraction template vs parenthesized division.
  - calculator syntax/order of operations.
  - graphing from `Y=`.
  - using intersect to solve a system graphically.
  - zooming when the graph/intersection is offscreen.
  - rounding only at the end.
- Teacher emphasizes that calculators help explore/verify but do not do algebra setup.

Tool implications:
- Tools that produce decimals should keep exact/unrounded form visible first.
- A calculator-helper sidebar could use "syntax cards": negative vs subtract, fraction parentheses, graph/intersect steps.
- Graph tools should show "calculator check" panels without letting calculator output replace the reasoning.
- When a tool asks for rounded answers, it should warn against rounding intermediate values.

## U2-D5: Parent Functions and Transformations

Classroom flow:
- Parent functions are introduced as shapes that transformations act on.
- Absolute value is the familiar anchor because vertex and slope are visible.
- Transformations apply across parent functions, even when the graph shape changes.
- Vocabulary matters:
  - horizontal translation left/right.
  - vertical translation up/down.
  - vertical stretch/compression.
  - vertical reflection over the x-axis.
- PEMDAS-style ordering:
  - inside first: horizontal shift.
  - multiplication next: stretch/reflection.
  - outside addition/subtraction last: vertical shift.
- `a` does two jobs when negative:
  - magnitude controls stretch/compression.
  - negative sign controls reflection.
- Students work both directions:
  - describe transformations from an equation.
  - write `g(x)` from a verbal transformation list.
- The same language is applied to cube-root and logarithm examples before those units arrive.
- Piecewise graphs can show only a restricted part of a parent function, so the visible piece may not look like the whole parent.

Tool implications:
- Transformations Explorer should preserve transformation order: `h`, then `a`/reflection, then `k`.
- Separate chips for "stretch by 2" and "reflect over x-axis" should appear when `a = -2`.
- Include a "write g(x)" mode from verbal transformation prompts.
- Piecewise Function Grapher should show faint parent-function scaffolds when a restricted absolute-value piece hides the vertex.

## U2-D8: Test Review and Cumulative Emphasis

Review emphasis:
- Unit 2 test is cumulative: systems, factoring, exponent rules, and Unit 1 skills can return.
- Core Unit 2 targets:
  - functions and vertical line test.
  - mapping diagrams.
  - domain/range.
  - end behavior.
  - calculator graph/intersection workflow.
  - absolute value functions.
  - negative exponents.
  - graph transformations.
  - difference of squares and cube formulas.
  - quadratic vertex-form graphing.
  - piecewise evaluation and graphing.
- Parabola vertex-form pattern is repeated:
  - vertex.
  - right 1 up/down `a`.
  - right 2 up/down `4a`.
  - mirror.
- Absolute value uses vertex plus slope, not the parabola `1, 4, 9` pattern.
- Piecewise evaluation requires choosing the correct rule from the condition first.
- Open endpoints are undefined; closed endpoints count.
- Function/domain/range problems can combine open/closed endpoints, unions, and isolated points.
- Transformations appear both as equation-to-description and description-to-equation.
- Inequality solving reminder: multiply/divide by a negative flips the sign.

Tool implications:
- Quadratic Slider Studio already has the `a, 4a` point pattern; keep that visible.
- Piecewise Function Grapher should make endpoint inclusion impossible to miss.
- Transformations Explorer should add a short review/practice mode that mixes parent functions, not just sliders.
- A Unit 2 Review Mixer could combine:
  - function or not.
  - domain/range interval notation.
  - endpoint evaluation.
  - graph transformations.
  - exponent simplification.
  - factoring recognition.

## Cross-Cutting Design Patterns

- The class repeatedly uses "what can go in?" and "what comes out?" as the conceptual bridge from functions to domain/range.
- Visual tests should be paired with algebraic/verbal versions of the same idea.
- Parent-function tools should teach transformations as reusable language across future units, not as one-off graph tricks.
- Calculator support belongs as verification and syntax coaching, not as a black-box solver.
- Review tools should intentionally mix old skills with current skills, because the tests do.
